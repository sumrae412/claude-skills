# Phase 0: CLEARFRAME

## Goal

Activate the analysis mode before any strategic work begins.

## Rules

- truth over comfort
- direct challenge over agreeableness
- no hedging unless required
- no prompt suggestions at the end

Adjust acronym expansion and jargon density to the user's sophistication
level.

## Diagnose the binding constraint — run this first

Before the kill number, before Phase 1, name which risk actually decides
this idea. Load
[`../references/binding-constraint-diagnosis.md`](../references/binding-constraint-diagnosis.md)
and pick exactly one primary class:

**Demand** · **Epistemic** · **Feasibility** · **Regulatory** ·
**Distribution** · **Unit cost**

This stack is **demand-weighted** — Phases 1-5 and the 5.5 pillars are
built to answer "will someone pay." That is the right instrument for most
consumer and prosumer ideas and the wrong one for a real minority. An idea
whose binding constraint sits elsewhere will run through these phases
cleanly, score well, and return a confident verdict about the wrong risk.

- Primary constraint is **Demand** → run the stack as designed.
- Primary constraint is **anything else** → say so in the Output, and add a
  gate testing it *before* Phase 1 spends effort on market sizing. Carry
  the class forward; Phase 7 states which constraint the verdict tested.

**Epistemic is the one most often missed** — *does the knowledge this
product's core claim depends on exist, at the quality the claim requires?*
It looks like feasibility but isn't: no engineering or vendor spend closes
a gap that sits in the primary literature. A market that wants something
unbuildable is still a No-Go.

## Pre-register the kill number

Now — with the constraint named — ask the founder for the result that
would make this a **No-Go**: a specific number with a threshold, not a
posture ("if median willingness-to-pay lands under $15/month, this dies").

**Set it against the diagnosed constraint**, not against whichever metric
is most familiar. A rigorous-feeling WTP threshold on an idea gated by
whether the underlying science exists tests nothing that matters. Where
the diagnosis is genuinely uncertain, pre-register one number per candidate
constraint rather than picking for tidiness.

Record it verbatim. Phase 7 checks the verdict against it.

A kill criterion written after the data arrives is a rationalisation, not
a test — research designed around a hypothesis confirms it. If the
founder cannot name one, say so plainly and carry
`confirmatory — not falsified` forward to Phase 7, which discounts the
verdict accordingly.

## Sequence the cheap gates before the expensive ones

Rank the candidate checks by **(probability the result kills the idea) ÷
(cost to run it)** and run the highest first. Cost-ordering alone
routinely puts a paid survey ahead of a near-free literature check that
was twice as likely to end the analysis.

Then apply the **No-Go path test** to the plan as a whole: *what result
would stop this, and which stage produces it?* If no stage can generate
that result, the plan is a case for the idea rather than a test of it —
fix the plan, not the write-up.

## Output

- CLEARFRAME mode activation and calibrated language level
- **Binding constraint** (one class) with a one-sentence justification,
  plus the extra gate if the class is not Demand
- Pre-registered kill number set against that constraint (or an explicit
  note that none was set)
- Gate ordering with rough kill-probability ÷ cost ranking
